Security Policy

Last updated: 2 September 2026

This Security Policy describes how AD Lab Development (“we”, “us”) secures the Atlassian Forge app Ticket Quality Auditor (the “App”).

1. Platform

The App runs entirely on Atlassian Forge. Core product logic, storage, and optional AI inference use Atlassian-hosted services (Forge functions, Forge app storage / KVS, and Forge LLMs). The App is designed for Runs on Atlassian eligibility: no third-party AI egress and no Remotes/Connect backends for core functionality.

2. Authentication and authorization

  • Access is granted through the customer’s Atlassian Cloud install of the App
  • API calls use Forge’s installation identity (asApp)
  • User-initiated actions call the Forge Authorize API before asApp() Jira access
  • Configuration is managed from the App’s admin UI by Jira administrators
  • Customers are never asked for Atlassian Personal Access Tokens, passwords, or shared API secrets for App use

3. Permissions (scopes)

The App requests least-privilege scopes:

  • read:jira-work — read issue content and receive issue events
  • write:jira-work — apply confirmed ticket improvements and optional comments
  • storage:app — persist configuration and analysis results

4. Data handling

  • Issue-derived analysis and configuration are stored in Forge app storage (installation-scoped)
  • When AI is enabled, selected ticket text is processed by Atlassian-hosted Forge LLMs
  • When AI is disabled, analysis is deterministic (rules/scoring only)
  • No separate customer database is operated outside Atlassian for core App state

5. Logging

The App emits structured operational logs (for example: product id, execution id, issue key, score, duration). Sensitive fields such as tokens and secrets are redacted. Logs remain within Atlassian Forge logging. We do not share logs that include End-User Data with third-party entities.

6. Network egress

The App does not define customer-managed egress for core functionality and does not expose remote REST APIs for third-party tool integration. There is no third-party AI provider egress.

7. Vulnerability reporting

Report suspected security issues to security@adlabdevelopment.com. Please include enough detail to reproduce the issue and avoid sending production secrets in clear text when possible.
